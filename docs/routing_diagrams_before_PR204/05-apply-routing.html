Apply_Routing

Post-processing of the routing graph: inversion, queue ordering, and optional reporting of unresolved routes.

Previous file: FindLower. After this, go back to Calculate_routing overview if you want the full loop again. 
flowchart TD
    A[Start Apply_Routing] --> B[Call Invert_routing on the Routing table]
    B --> C[For each cell, collect all upstream parents]
    C --> D[Break problematic pairwise rings when necessary]
    D --> E[If a cell has no target, FindLower may assign one here]
    E --> F[Initialize treated-state arrays]
    F --> G[Allocate row and column arrays for processing order]
    G --> H[Find starting points with no upstream parents]
    H --> I[Put those starting points into the queue]
    I --> J{Are there still cells left in the queue?}
    J -- Yes --> K[Take the next queued cell]
    K --> L[If Part1 exists, mark this parent relation as treated for Target1]
    L --> M[If Part2 exists, mark this parent relation as treated for Target2]
    M --> N{Did a target cell now receive all of its upstream parents?}
    N -- Yes --> O[Append that target cell to the queue]
    N -- No --> P[Continue]
    O --> Q[Advance to the next queue entry]
    P --> Q
    Q --> J
    J -- No --> R{Is Write_routing enabled?}
    R -- Yes --> S[Write routing_missing.txt for unresolved cases]
    R -- No --> T[Finish]
    S --> T
